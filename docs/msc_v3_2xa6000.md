# 双 A6000 训练

基础配置：[msc_v3_2xa6000.yaml](../configs/msc_v3_2xa6000.yaml)，启动参数集中在
[train.sh](../train.sh) 顶部。
Text、Audio 均为每卡 batch 1152，使用全体窗口的全局伪随机排列，每轮无放回遍历，不设置分任务 batch 或固定交替规则。

| 设置 | 值 |
| --- | --- |
| GPU | 0、1，RTX A6000 48GB |
| 架构 | 12 层，Hidden 1024，16 Heads，FFN 3072 |
| 可训练参数 | 296,883,767 |
| 精度 | BF16 autocast/梯度通信，参数及 Adam 状态 FP32 |
| 每卡 / 全局 batch | 1152 / 2304，累积 1 |
| 停止条件 | 30,000 steps |
| 学习率 | 峰值 1e-4，warmup 1000，cosine 衰减到 1e-6，schedule 30000 |
| 辅助损失 | 默认关闭（速度 0、加速度 0），只使用 Flow Loss |
| DataLoader | 每卡 8 workers，每 worker cache 512MiB |
| 验证 / 保存 | 脚本默认每 2000 / 10000 步，由 rank 0 执行 |
| RTC / Video | 默认关闭 |

现有 Train 池共 68,302,686 个窗口；30,000 steps 处理约 69,120,000 个样本，
约为一轮。采样器按数据量自然覆盖任务，不重加权，也不按 epoch 停止。

## 启动

先为当前 Train pool 生成精确统计量，再启动训练：

```bash
bash train.sh --stats
bash train.sh
```

`.venv/bin/python` 是默认解释器，可用 `MSC_PYTHON` 覆盖。
输出目录由脚本 `OUTPUT_DIR` 指定，编译缓存默认位于 `.runs/msc-v3-compiler-cache`。
运行产物不随仓库分发；没有统计量时，不能直接复用历史目录路径启动训练。
本页提供启动方法，不表示训练进程当前仍在运行。

## 修改启动参数

`train.sh` 按 GPU、优化器、日志/验证、数据、模型、辅助损失和运行时分组，
可以直接修改各变量的默认值，也可以临时通过环境变量覆盖。
优先级为：末尾 `section.key=value` > 环境变量 > 脚本默认值 > 对应 YAML 值。

```bash
# 单卡、小 batch；调度长度默认跟随 STEPS。
CUDA_VISIBLE_DEVICES=0 BATCH_SIZE=128 STEPS=2000 WARMUP_STEPS=100 bash train.sh

# 末尾配置覆盖优先级最高。
BATCH_SIZE=512 bash train.sh train.batch_size=256 train.wandb_name=trial
```

`BATCH_SIZE` 是每卡 microbatch，全局有效 batch 为
`BATCH_SIZE × NUM_GPUS × ACCUMULATION_STEPS`。
默认进程数由 `CUDA_VISIBLE_DEVICES` 中的 GPU 数量确定，可用 `NUM_GPUS` 显式覆盖。
`CACHE_MB` 是每个 DataLoader worker 的缓存 MiB，`STATS_WORKERS` 控制统计进程数。
数据根目录和任务使用 YAML 列表，例如 `TASKS='[text, audio]'`；
可选子集限制、resume 和 W&B 名称使用 `null` 表示不设置。

修改数据根目录、任务、对齐策略或子集后，用相同参数重新运行 `bash train.sh --stats`。
它复用训练覆盖项，将统计量写入最终 `model.dynamic_stats_path`，不启动训练。
G1 125D、30 FPS、5/30 帧和冻结 Encoder 为固定契约；Video K/D 默认从真实元数据读取。

## 学习率与 checkpoint

保留线性 warmup，峰值由 `LEARNING_RATE` 控制，随后 cosine 衰减到
`MIN_LEARNING_RATE=0.000001`，到达调度末尾后保持该下限。
warmup 初期可以低于这个最终衰减下限。设为 `0` 可使用衰减到零的设置。

本地 OMG `configs/generation/exp/300m.yaml` 使用峰值 `1e-4`、warmup 2000、
总调度 180000、下限 `1e-6`；Psi0 `src/psi/config/config.py` 的通用默认是
`cosine_with_min_lr`、下限 `5e-7`，具体任务可覆盖。
MSC 采用非零下限的方式，仍保持自身 1000-step warmup 和 30000-step 调度。
这是调度选择，不代表已经完成不同下限的收敛效果对照。

`CHECKPOINT_EVERY` 按 optimizer step 保存完整训练状态，例如当前默认：

```text
OUTPUT_DIR/checkpoints/step_5000.pt
OUTPUT_DIR/checkpoints/step_10000.pt
...
OUTPUT_DIR/checkpoints/step_30000.pt
```

末步即使不是保存间隔的整数倍也会保存；此前的 step 文件保留。
采样、评估或 `RESUME` 指向选定的 step 文件，不再依赖 `last.pt`。

## W&B 离线日志

项目名由 `WANDB_PROJECT` 覆盖 `train.wandb_project`，使用 `mode=offline`，无需登录。
依赖通过 `pip install -e '.[tracking]'` 安装；双卡仅 rank 0 创建 run。
离线文件保存在 `OUTPUT_DIR/wandb/offline-run-*/`。
原有 `metrics.jsonl`、`validation.jsonl` 和 `profile.json` 继续保留。

按 `log_every` 记录已有训练指标，包括分任务 Loss、学习率、梯度、吞吐及各卡显存；
验证指标按 `validation_every` 记录，训练配置和最终 profile 也会保存。
训练和验证共享真实 optimizer step 横轴，不启用额外模型梯度追踪或权重上传。

`loss` 为最近日志区间内各 optimizer step 的平均损失，`step_loss` 保留区间最后
一步的损失；两者均包含梯度累积，并在多卡间取平均。区间均值方便观察趋势，
单步值用于定位尖峰。已有训练日志的 `loss` 使用原来的单步口径，不会被追溯修改。

训练日志和 W&B 同步记录以下速度字段：

- `seconds_per_step`：最近日志区间的每次 optimizer 更新耗时。
- `interval_samples_per_second`：同一区间的全局样本吞吐，包含梯度累积。
- `eta_hours`：按该区间速度外推的剩余训练小时数。
- `samples_per_second`：从本次启动开始的累计平均吞吐。

首个区间包含首次编译；后续区间包含期间的验证和保存耗时。
区间估计会随任务、辅助损失启用和编译变化，不是完整训练的固定耗时保证。

```bash
bash train.sh train.wandb_name=msc-v3-first-run
# 如需关闭：bash train.sh train.wandb_project=null
```

本机直接 NCCL P2P 曾停滞，因此 `train.sh` 默认使用已测的共享内存通信路径。
`CUDA_VISIBLE_DEVICES`、`MASTER_PORT`、编译缓存和分配器设置可通过环境变量覆盖。

## 已采用的优化

- 按 batch 解码所需 Parquet row group，复用有界缓存，批量 FK 和 Codec。
- 标量 Flow 时间调制广播，RTC 仍使用逐帧时间。
- 冻结 T5 在线编码，batch 内去重并按原样本顺序还原，动态补齐至当前最长文本。
- 原位编译 Expert、fused AdamW、BF16 梯度通信，模块梯度统计只在日志步执行。
- 互斥外部模态共享补齐槽位，保留全部有效 token、Mask、模态 ID、时间和 Video support。
- `expandable_segments:True` 减少输入形状变化造成的显存碎片。

BF16 梯度通信会引入舍入。此前独立双 rank 对照相对梯度误差约 0.2%，两 rank 更新一致。

## 历史硬件测量

以下数值来自 2026-10-23 的本机测试，PyTorch 2.7.0+cu126 / Triton 3.3.0；
原始 `.runs` 日志目前不在工作区，数值作为历史测量保留，不作为本次重新执行的结果。

| 测量 | 结果 |
| --- | --- |
| 优化前，batch 576/卡 | 3.14 秒/step，367 样本/秒 |
| 最终 batch 1152/卡，Text warmup 第 10–40 步 | 1.051 秒/step，2,193 样本/秒 |
| 最终 Text 段峰值 | 约 35.9 GiB allocated、36.0 GiB reserved |
| 1152/卡混合容量测试，辅助损失开启 | 45.34 GiB allocated、45.40 GiB reserved |

容量测试以重复长文本和真实 Audio 特征构成压力输入，只证明前后向容量。
Text warmup 速度不包含完整音频段、辅助损失启用后的额外开销、验证、保存和首次编译。
显存利用率随条件长度变化，允许文本批次存在显存余量。
